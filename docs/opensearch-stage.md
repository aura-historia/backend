## Reproducible host setup

Docker Engine/Compose, `jq`, >=16 GiB of spare RAM, suitable persistent disk and `vm.max_map_count >= 262144` are needed; this host reported 16438223. Restrict Docker group/socket access (equivalent to root). From the repository root, create a private mode-0600 `opensearch/stage/.env` containing a strong random `OPENSEARCH_INITIAL_ADMIN_PASSWORD` with upper/lowercase letters, digits and punctuation. The public profile defaults to the relative `opensearch/stage/certs/` bind mount; `OPENSEARCH_CERT_DIR` is an optional override. Private `.env`, `.admin-curl`, `.credentials/` and `certs/` are Git-ignored. Store copies in an access-controlled backup/secret store, never in Git, tickets or logs. `docker inspect` exposes environment variables to Docker operators. Keep administrator credentials separate from AWS runtime credentials.

```sh
docker compose --env-file opensearch/stage/.env -f opensearch/stage/compose.yaml up -d opensearch
```

On a **fresh** volume only: the image installs the bundled demo security config behind loopback. Before ever starting `gateway`, replace the admin password, rotate the reserved `kibanaserver` password and delete all unused demo users. The reserved accounts cannot be edited with the Security REST API: use the image's `securityadmin.sh` to back up the current `internalusers` configuration, change only those hashes and reapply only `-t internalusers`; do **not** upload the entire demo configuration or overwrite the runtime users. Then sync the private `.env` and restart the container; verify the old admin password fails. This was done on this host. Do not reuse the bundled node/admin certificates as a public trust chain. The loopback-only node uses image-internal self-signed HTTPS. The gateway's upstream is on the private Docker bridge; its `tls_insecure_skip_verify` applies **only** to that internal hop, never to clients.

Use an admin-only local curl config (mode 0600, Basic credentials and `insecure` for the *loopback* self-signed node) at `opensearch/stage/.admin-curl`; do not put passwords in shell history or command arguments. On a new installation create role documents from `opensearch/stage/roles/*.json` via `PUT /_plugins/_security/api/roles/aura_stage_<role>`; privately create a distinct random-password internal user `aura_stage_<role>` with `opendistro_security_roles: ["aura_stage_<role>"]` for each role. The four roles are `reader`, `product_projector`, `filter_projector`, `percolator` (file names use hyphens). Reader searches the two application indexes; projectors only index their respective documents; percolator searches saved filters and creates/closes PITs. No runtime user has security/cluster administration, index management or unrelated-index access. Rotate users via the security API and then their SSM references as a controlled operation, never during an ordinary Lambda release.

Never recreate existing indices, reset aliases, delete documents or reapply old security backups as part of code deployment. Subsequent mapping changes and rebuild/alias cutover belong to controlled #1803 operations. Routine `docker compose up` preserves `stage_data`; **never use `down -v`** on a populated volume. A normal CDK/Lambda release only reads SSM references and has no host lifecycle hook. ## Public TLS and AWS gate

The gateway profile uses Caddy at `https://opensearch.stage.aura-historia.com:9443`, independently of the existing `internal-agent.aura-historia.com` service on 80/443/8080. It proxies only application search/projection/percolation paths; admin APIs are not routed. The certificate and Certbot state are in the private, Git-ignored `opensearch/stage/certs/` directory (including `live/` symlinks into `archive/`); the whole directory is mounted read-only into Caddy. Do not copy only the `live/` directory or check certificate keys into source control. `OPENSEARCH_CERT_DIR` can override the default bind source for another host. Caddy does not bind 80/443 or perform ACME challenges itself.

To issue on a **new** host, first ensure the A record points at that host and port 80 is available and reachable. Then, from repo root:

```sh
docker compose --profile cert --env-file opensearch/stage/.env -f opensearch/stage/compose.yaml run --rm --service-ports certbot certonly --standalone --preferred-challenges http --non-interactive --agree-tos --register-unsafely-without-email --config-dir /etc/letsencrypt --work-dir /etc/letsencrypt/work --logs-dir /etc/letsencrypt/logs -d opensearch.stage.aura-historia.com
```

The pinned Certbot 5.8.0 image temporarily publishes port 80 **only while that command runs**. Issuance and a `certonly --dry-run` succeeded on this host. No notification email is registered: the operator must monitor expiry independently. Do not run this profile if another service owns port 80; coordinate a brief window or switch to DNS-01.
