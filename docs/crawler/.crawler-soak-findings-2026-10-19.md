## Findings, ranked for small/medium shops

### 1. Rare template variants still re-block a freshly approved source — extends #2116, #1581

- Two of five sources needed a post-approval fix within 10 minutes despite 25-page live checks: Heymann (single photo, no thumb strip; required `images` matched nothing) and Moxhams (unsold item without a price). Each cost an LLM call and, for Heymann, a human review.
- Moxhams also showed that the deterministic check runs only on the seed pages; 5 of 40 extra pages (sold without price) would have failed.
- The fresh Heymann candidate kept the approved schema and appended a worse one (`<title>`, a different identity source); approving it would have split identities.
- Fix direction: let the reviewer or the gate evaluate a candidate on N random stored product URLs of the source, not only seeds (#1581, finding 9 of 2026-10-18).

### 2. Initial schema generation runs on a single half-open probe page — not ticketed

- Hansord's first scrape hit a 429, the circuit opened, and the next attempt was a domain probe. `collect_schema_seed_pages` returns only the primary page in `ScrapeMode::DomainProbe` (`seed_pages.rs:41-44`), but initial generation still ran, on one sold page. The resulting schema could only extract sold items.
- Fix direction: defer initial generation until a normal-mode scrape, or sample seeds once the probe succeeds.

### 3. `state` is mandatory, so shops without availability text get junk states — not ticketed

- `ProductCssSelectorSchema.state` and `images` are required rules (`product_schema.rs:86-91`); a candidate without state is rejected as `invalid ProductSchema review candidate`.
- Four of five shops have no availability text on unsold pages; the LLM chose "send enquiry", "Enquire", "Add to basket to request a price" and nav menu labels. Denzil Grant marks sold only through the post type or a free-text "SOLD" paragraph; Moxhams only through a banner image.
- None of these resolve in normalization, so Moxhams' 14/25 sold items and Denzil's archive are not marked sold (Hansord's "Sold" text worked: 94 URLs went dormant).
- Fix direction: make `state` optional (unknown availability), and allow a rule that maps "selector matched" to a constant label (sold banner present → `sold`).

### 4. No stable identity on some server-rendered shops — extends #2098

- Puritan Values exposes its SKU (`PV004767`) and availability only in JSON-LD; the extractor cannot address JSON-LD fields, and #2188 now skips `script` content entirely. The stored URL slugs already differ from the current slugs (items are renamed), so URL-derived identity is unstable too. The approved schema uses the PDF tear-sheet link, which embeds the slug.
- JSON-LD is invisible at both stages: the YAML projection removes every `script` before generation (`projection.rs:10-12`, enforced by `should_not_project_product_json_ld_scripts` since #1126, no documented rationale), and text extraction skips `script` subtrees (`rule.rs:254`).
- Fix direction: project a compact JSON-LD `Product` summary for the LLM and add an extraction kind that reads JSON-LD fields (`sku`, `offers.availability`, `offers.price`).

### 5. Text-anchored selection is impossible — not ticketed

- Denzil Grant's price, "SOLD" and `Ref:` sit in unlabelled paragraphs whose order varies; Heymann's facts rows and Puritan's attribute rows shift by item. The selector engine has no `:contains`/label-anchored matching, so price, measurements and most raw attributes were dropped on three of five shops.
- Fix direction: a label-anchored rule (`dt` text → next `dd`, or paragraph starting with "Price:").

### 6. Availability vocabulary misses quantity labels — extends finding 14 of 2026-10-18

- "Unikat - 1 Stück verfügbar" and "One-of-a-kind - 1 piece available" (Heymann) do not match the quantity regex, which expects the number directly before `verfügbar`/`available`. All 157 Heymann captures have an unresolved state.

### 7. Spider and scraper hit the same domain concurrently; Retry-After ignored — #1913, #2120

- Hansord answered 429 to the scraper at 20:49 while the spider was mid-crawl (`spider_active_on_domain=true`), with the honest agent. The circuit waited 10 min instead of the 41 s `Retry-After`; harmless here, but it shows the circuit does not use the header.
- 593 of Hansord's 888 crawled URLs carried a query string (#2119, #2114).

### 8. Discovery budget: crawl-delay shops and language duplicates — #2119, #1491

- Puritan Values (robots `Crawl-delay`) yielded 59 URLs in 600 s, about one page per 10 s, and only 20 product URLs out of a 3,769-entry sitemap. The sitemap is not read (#2119).
- Antik Heymann serves each item under `/antiquitaeten/…` and `/en/antiquitaeten/…`; both are stored and scraped, with the same identity, so the listing alternates between German and English captures.

### 9. Observability (new items only) — #2117

- A `SchemaRegenerationExhausted` URL stores only the failed LLM schema's error ("no element matched `div.description_area > h2`"), not why the approved schemas did not apply (here: no price). It misled the first diagnosis.
- `log-summary.ps1` misses spider outcomes: it matches `Crawl completed successfully`, but the binary now logs `Crawl completed`. The monitor filter of this soak missed the first reviews for the same reason.
