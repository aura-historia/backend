## Findings, ranked for small/medium shops

### 1. A 403 to the stale spider user agent is reported as a robots denial — #2113, **fixed and verified in round 2**; merged as PR #2152 (a97d2e0af, 21:14 UTC)

- lennoxcato.com answers 403 to `Chrome/114.0.0.0` (`website_spider.rs:25` at 2f7e2bdcb) on `/robots.txt` and the root, apex and www. Every other agent, including `AuraHistoriaBot/1.0`, gets through. Second shop after inanutshellantiquesandinteriors (2026-10-15).
- `apply_local_filter_outcome` (`website_spider.rs:1029-1037`) turned the refused robots request into `AccessDenied` / `robots_txt_request_denied` with a 6 h cooldown, without the HTTP status.
- Round 2 on the fix branch: both shops crawl to completion and scrape fully, and 1,017 pages on three previously working shops show no regression (see "Round 2"). The new `crawl_root_access_denied` path was not exercised because no shop refused the honest agent. The branch was merged as PR #2152 after the round.

### 2. HTML entities in hrefs make a whole source unscrapable — #2114, severity understated

- antiquesbydesign.co.uk links are `single.asp?c=&amp;offset=20&amp;id=113` (correct HTML). The spider stores `single.asp?amp;id=113&amp;offset=20&c=Misc`: 1,168 of 1,179 URLs. The server ignores `amp;id` and renders an empty product, so no schema can pass and the source is dead while its pattern is MATCHED with 294 product URLs.
- `CrawledUrl::new` (`spider/utils/url.rs:36-57`) only strips the hash and trailing slash; nothing decodes entities. The pattern `single\.asp\?.*id=.*` accepts the mangled form (#2109). The 1,374-entry sitemap is never read (#2119).
- Every review action on this source costs an LLM call (finding 3), so the review stays pending until #2114 lands.

### 3. A rejected, repaired or dropped candidate comes straight back — not ticketed

- NEEDS_REPAIR on Antiques By Design at 18:07:18 → a new review with identical selectors 36 s later, now HIGH/APPROVE.
- Marhamchurch: after the 19:07 approval dropped the LLM's `og:image` schema, the same page regenerated the same schema at 19:09.
- Nothing in `src/crawler/src/scraper` reads `NEEDS_REPAIR` or `REJECTED`, and reviewer notes and dropped candidates are not fed back into generation. Each round trip costs an LLM call and re-blocks the source.
- Fix direction: per-URL and per-source generation cooldown after a reviewer decision, reviewer notes and failing fields as correction feedback, and a "known bad" list of dropped candidates.

### 4. A shop rate-limited the scraper after our crawl — #2120, #1913; **did not recur with the honest agent**

- Round 1: hickmet.com (Shopify, behind Cloudflare) was spidered at about 2 pages/s for 600 s with the Chrome/114 agent. Every scrape attempt afterwards got 429 (17:58, 18:02, 18:22, 19:03), the circuit cooldown escalated to 60 min, and after 100 minutes the source had zero captures.
- Round 2: the same crawl volume (1,012 pages in 600 s) with `AuraHistoriaBot`, then 109 scraped pages in full 50-URL batches with no 429. The stale browser agent, not the crawl rate alone, most likely triggered the rate-limiting; a pinned old Chrome version is a common bot-scoring signal. This is one shop over one evening, so the rate question is not closed.
- Still valid: the spider does not count its own 429/403 pages (#2120), and spider and scraper share no per-domain limiter (#1913). Re-check antik-heymann (429 on 2026-10-15) with the new agent before ranking this high again.

### 5. `additional_selectors` aggregate; they are not fallbacks — not ticketed

- `ExtractionRule::apply` (`rule.rs:140-195`) runs the primary and every additional selector and concatenates the results. With `cardinality: first` that is harmless for single-valued fields (the first result wins), but for `description` and `images` with `cardinality: all` every "fallback" adds its matches.
- During review I added fallbacks to make optional `description` rules robust (18:25). Wick, Van Leest, Vauclair and briefly Marhamchurch then captured descriptions up to nine items long, with the container, the paragraphs and the title, and Van Leest and Vauclair captured every image twice. Corrected at 19:12 with single selectors that cover every variant (`container > *`, selector groups and a separate no-description schema). Vauclair's 158 captures from 18:25–18:49 still carry the duplicated descriptions.
- The LLM uses `additional_selectors` the same way (Vauclair title, earlier rounds), and neither the review gate nor the console shows the aggregated value.
- Fix direction: decide the contract. Either make additional selectors fallbacks for multi-valued fields, or keep aggregation, deduplicate results, and say so in the schema description shown to the model and the reviewer.

### 6. An optional field that matches nothing re-blocks a freshly approved source — #2116, now with review cost

- Three of four approved sources were blocked again within six minutes because one page lacked the element of the optional `description` rule (`product_schema.rs:216-222`). Each block cost an LLM call and a human review.
- Images already have the right behaviour: an image rule whose container exists but holds no image yields an empty list (`product_schema.rs:173-186, 304-340`). This is what made photo-less Marhamchurch and Antik Wolf pages extract honestly. `description` and `price` need the same rule.

### 7. Identity silently changes across template variants — extends #2098

- Wick's original identity selector (the inquiry form) is missing on sold pages, so `source_listing_id` fell back to a 64-hex hash for 22 of 198 captures. When the item later sold, its identity would have changed from the post id to a hash.
- Round 2 repeated it twice on Lennox Cato: some products have no SKU, and many archived pages drop the quote button that carries the post id, so 26 of 220 captures got a hashed identity before the identity moved to the gallery's `data-product-id`. Hickmet's POA pages lack the `product-id` input the LLM chose.
- Fix direction: the review gate should apply the identity rule to sold, archived and POA pages and fail when identity is empty on any of them; prefer IDs present on every variant (form container post id, gallery product id, canonical, `postid-` body class).

### 8. Discovery budget and query URLs — #2119, #2114, #1491, #2115; #1912 verified fixed

- All six crawls are recorded `HARD_TIMEOUT_TRUNCATED`, keep their URLs and recrawl in 24 h: #1912 works.
- The budget went to Vauclair `?s=` search (262) and `?lang=en` duplicates (199), Hickmet `?q=` (151) and pagination, Wick `?s=` (33) and `pagec` (34).

### 9. Review console and API gaps — #2090, partly #2056; editing parts not ticketed

- The field editor (`schema_payload.rs:73-99`) accepts only core fields: raw attributes cannot be edited and schemas cannot be added on an approved review. Two category-path fixes and the 19:12 corrections had to be written to `listing_source_product_schemas` directly, so the live lists and their review candidates now differ.
- Editing any approved review rewrites the whole live list from that review's candidate (2026-10-14 note), so a later field edit through an older review would revert those changes.
- The matrix evaluates only a review's own pages. There is no way to test a candidate on a sold, POA or photo-less page of the same source before approving.
- A pending review of a disabled source stays at the top of the queue (Antik Wolf until 19:13).

### 10. Observability (new items only) — #2117, #2125

- `Scraper scheduler pass complete` has no per-domain breakdown; `skipped=147` does not say which sources were blocked by review, budget or circuit.
- The library's `crawl hard timeout after 600s` WARN and our `Spider run truncated by hard timeout` are two records per crawl with different keys.
- Throughput: 1.7–2.2 s per URL end to end (debug build), consistent with 2026-10-15; Hickmet about 10 s per URL with 11–12 images per page (#2124).

### 11. Seed pages miss the template variants that break a schema — #1581, extends #2116

- Every new shop in round 2 needed two or three review rounds: Lennox Cato failed on archived pages, then on POA in an `h3`, then on POA in a paragraph; Hickmet failed on nested pasted descriptions, then on POA pages. Each failure cost an LLM call, re-blocked the source and needed a human review.
- Initial generation saw one to four seed pages, all of the common template. The variants that matter (sold, archived, POA, photo-less, pasted markup) are rare in a random sample.
- Fix direction: choose seeds by template diversity (#1581) and let the reviewer evaluate a candidate on arbitrary URLs of the source (finding 9).

### 12. The extractor cannot read CSS background images — not ticketed

- In A Nutshell (Ecwid) renders every gallery photo after the first only as `background-image:-webkit-image-set(url(...))` on thumbnail elements. `image_url_candidates_for_element` (`rule.rs:269-321`) reads `data-*`, `href`, `srcset` and `src` only, so the shop's listings carry one photo each.
- Fix direction: parse `url(...)` from inline `style` background images as an image candidate.

### 13. Text extraction includes `<style>` and `<script>` content — not ticketed

- Hickmet's POA notice is bare text sharing a `div` with an inline `<style>` block. Text extraction of that `div` returned the notice plus the CSS rules, and the LLM's fresh schema used it as both price and state. The review gate accepted it.
- Fix direction: skip `style`, `script` and `template` subtrees in text extraction.

### 14. Availability vocabulary misses common dealer labels; sold prices render as zero — not ticketed

- Normalization matches whole labels only (`availability.rs:103-134`). "ITEM SOLD" (Hickmet), "Make An Enquiry" and "Archive" (Lennox Cato) and "contact us" stay unresolved; only "ADD TO BASKET" and schema.org links resolved this round.
- Ecwid renders sold items with a price of £0.00, and neither the gate nor price normalization rejects a zero price; only the schema split kept it out of the data.
- Fix direction: extend the sold/enquiry vocabulary with real dealer labels, and add a plausibility check that rejects a zero price.
